## Устройство кода

```
src/TiaMcpServer/
  Program.cs, CliOptions.cs        запуск, флаги --read-only, --tools, --full, --debug-tools, регистрация
  ModelContextProtocol/            слой инструментов: partial class McpServer, типы запросов и ответов
    McpServer.cs                   общие помощники: Guarded, ToolError, Created, Deleted, OkMeta
    McpServer.<Область>.cs         инструменты области (Blocks, Tags, Hardware, Unified, Libraries...)
    Unified*.cs, Response*.cs      типы действий и ответов
    WritePolicy.cs                 [WriteTool], [DebugTool]
    ToolSets.cs, ToolGroups.cs     области (--tools) и групповые инструменты - вид по умолчанию
    ToolCallGate.cs                вызовы инструментов идут по одному
  Siemens/                         слой Openness: partial class Portal
    Portal.cs                      подключение, проект, InTransaction
    Operation.cs, ErrorText.cs     Operation.Run - блокировка и оформление ошибок
    Portal.<Область>.cs            операции области
    Portal.Unified*.cs             WinCC Unified: экраны, элементы, фейсплейты, теги, алармы, списки
    SimpleYaml.cs                  чтение и запись YAML-файлов списков
    Classic/Portal.HmiClassic.cs   отложенное: классический WinCC, без инструментов
tests/TiaMcpServer.Test/           MSTest. Классы с категорией NoTia не требуют TIA Portal (189 тестов)
Install/TiaMcpServer/              готовая сборка, лежит в git; из неё работает сервер у Biz
tools/                             скрипты разработки (см. tools/README.md)
docs/handoff/                      этот пакет: контекст, рецепты, задачи, справочники API
```

Два слоя и правило между ними:

- **Инструмент** (`McpServer.*.cs`) — тонкий: описание, параметры, вызов `Portal`, сборка ответа.
  Изменяющий инструмент помечен `[WriteTool]` и обёрнут в `Guarded(...)` — это проверка режима
  записи и транзакция TIA Portal. Отладочный — `[DebugTool]`.
- **Операция** (`Portal.*.cs`) — вся работа с Openness, внутри `Operation.Run(...)`. Ошибки —
  `PortalException(PortalErrorCode, сообщение)`; коды и правила — в `docs/error-model.md`.

Готовые образцы и пошаговый порядок добавления инструмента — в `docs/handoff/recipes.md`.

## Правила, за нарушение которых платит пользователь

### 1. Внутри транзакции нельзя «поймать и продолжить»

Все изменяющие инструменты идут в транзакции TIA Portal. После **любого** исключения Openness,
даже перехваченного, TIA запрещает фиксацию: «Commit of a Transaction is not allowed after an
exception is thrown». Следствия:

- Пакетные операции — «всё или ничего». Нельзя писать `try { вариантА } catch { вариантБ }`.
- Тип значения брать из типа .NET-свойства (`PropertyInfo.PropertyType`), а не читать текущее
  значение атрибута «на пробу».
- Всё, что можно проверить заранее (существует ли таблица, тег, класс), проверять до вызова
  Openness и бросать `PortalException` — он исключением Openness не является и откат не портит.
- `Portal._inTransaction` говорит сообщению об ошибке, был ли откат.

### 2. Вызовы, закрывающие TIA Portal

Некоторые вызовы Openness завершаются `NonRecoverableException`, и TIA Portal закрывается вместе
с несохранённым проектом. За 05–06.10.2026 это случилось четыре раза. Известные:

| Вызов | Что делать вместо |
|---|---|
| Исключение, выпущенное из обратного вызова Openness (делегаты `DownloadProvider.Download`) | Внутри обратного вызова всё в `try/catch`, ошибки копить, не бросать |
| Запись `HmiTag.DisplayName` (Unified) | Отклонять до обращения к Openness; `Comment` пишется нормально |
| `GetAttributeInfos()` на аларме Unified (`HmiDiscreteAlarm`) | Только типизированные свойства; `AuditClass` не трогать вовсе |
| `MappingTable.Entries.Create<MappingTableEntrySimple>()` (строка таблицы Expression конвертера тега) | Не создавать; сервер таблицу Expression не предлагает |
| `DownloadProvider.Download(targetInterface.Addresses.Create("192.168.0.1"), pre, post, options)` — созданный адрес передан как сама конфигурация (07.10.2026; устройство при этом не отвечало с ПК) | Созданный адрес — только вторым аргументом: `Download(targetInterface, address, pre, post, options)`, и только если устройство отвечает на ping (так делает `download_to_plc` с `targetAddress`; проверено дважды, TIA Portal цел). Недостижимый адрес сервер отклоняет до вызова Openness |

Аудит общего доступа к атрибутам (06.10.2026, задача 05): на 34 видах объектов проекта, 39 создаваемых типах элементов
экрана и 17 видах устройств, блоков, типов и сетей `GetAttributeInfos` и чтение каждого атрибута **безопасны**; других
опасных видов, кроме аларма, не найдено. Список — в комментарии `Portal.Unified.cs`. Тест-страж `Test20` не даёт
общему доступу к атрибутам попасть в модули алармов, архивов, скриптов и групп экранов.

Когда вызов всё же закрыл TIA Portal, сервер это распознаёт (`TiaLoss`): отвечает «TIA Portal was closed by the call...»,
сбрасывает подключение, `get_state` показывает `isConnected: false`. Дальше — `tools/start-tia.ps1`, `connect`.

Правило: вызов на виде объектов, с которым сервер ещё не работал, **сначала пробуется отдельным
скриптом** через `tools/openness-probe.ps1` — по одному обращению, с отметкой перед каждым,
запись — в транзакции без фиксации. Для новых видов объектов использовать типизированные
свойства, а не общий доступ к атрибутам (`GetAttributeInfos`, `GetAttributes`, `SetAttribute`).
Перед пробой сохранить тестовый проект. Если вывод оборвался после строки `TRY` — этот вызов
закрыл TIA: перезапустить (`tools/start-tia.ps1`), записать вызов в таблицу выше и в комментарий
в коде.

После `NonRecoverableException` не вызывать `connect` вслепую: сначала проверить, жив ли процесс.

### 3. Прежде чем сказать «Openness этого не умеет»

Искать по всем сборкам, а не в одном классе: `tools/openness-reflect.ps1 -Name '<слово>'`.
Пример ошибки: интегрированное HMI-соединение «нельзя создать», потому что у
`HmiSoftware.Connections` партнёр только для чтения — а оно создаётся в аппаратной части,
`CommunicationManagement.Connections.Create<HmiConnection>(...)`.

### 4. Openness многое принимает молча

Несуществующее имя тега, класса алармов, списка, рисунка, экрана, соединения сохраняется без
ошибки; импорт списков отбрасывает непонятные записи без ошибки. Средств три:

- **`Validate()`** — собственная проверка TIA Portal, есть у большинства объектов Unified
  (теги, алармы, классы, архивы, элементы экрана, настройки runtime). Называет несуществующие
  ссылки и значения не по типу. Изменяющая операция читает её до записи и после
  (`WithUnifiedValidation` в `Portal.Unified.cs`): новая ошибка — отказ действия, прежние и
  предупреждения — в `Notes`. Новую операцию над объектом Unified оборачивать так же.
- **Проверять самому до записи** то, чего `Validate()` не видит: теги внутри формулы
  (`CheckFormulaTags`), теги триггера.
- **Читать обратно и сравнивать** то, что пишется через файл или может быть заменено молча:
  списки, скрипты, формула (`$value * 2` превращается в `'InvalidTag'`).

Синтаксис скрипта и формулы не проверяет ничто из этого — только компиляция HMI
(`unified_compile`). Она возможна лишь для устройства целиком и запрещена внутри транзакции,
поэтому отказать в записи не может: вызывается после пакета и сообщает найденное.

### 5. Сообщать честно

Что проверено вживую, что только модульными тестами, что не проверено совсем — писать прямо, в
ответе пользователю и в плане. Если что-то сломал (уронил TIA, потерял несохранённое) — сказать
первым делом.

## Рабочий цикл одной задачи

1. Прочитать файл задачи и справочник API, на который он ссылается (`docs/handoff/api/`).
2. Отражением уточнить API: `tools/openness-reflect.ps1`.
3. Пробой на тестовом проекте выяснить, как Openness ведёт себя на деле: `tools/openness-probe.ps1`.
   Что принимает молча, в каком порядке задавать свойства, что возвращает после создания.
4. Написать операцию в `Portal.<Область>.cs` и инструмент в `McpServer.<Область>.cs`.
5. `tools/finish.ps1` — окончания строк, сборка, модульные тесты.
6. Проверить вживую. Пока идёт разработка — `tools/inproc-call.ps1`: он вызывает инструменты
   сборки внутри PowerShell, и TIA Portal не спрашивает про доступ. Обязательно: удачный путь,
   ошибочные случаи, уборка за собой. На панели `HMI Unified/HMI_RT_3` и, где важно, на
   ПК-станции `АРМ Unified/HMI_RT_1`. Когда задача закончена — один раз через установленный
   сервер: `tools/mcp-call.ps1 -Grouped` (вид по умолчанию) и «дымовые» прогоны `tools/smoke.ps1`
   (чтение не меняет проект) и `tools/smoke.ps1 -Write` (каждый изменяющий инструмент, с уборкой;
   около 10 минут; проект должен быть сохранён). Новому изменяющему инструменту нужен вызов в
   `tools/smoke/write.json`, иначе прогон его назовёт.
7. Документация: `README.md`, `README_ru.md`, `Implemented_Tools.md`, `CHANGELOG.md`
   (раздел `[Unreleased]`), `docs/tools-list.txt`, список в `Test_703`, файл задачи и индекс
   `docs/handoff/README.md`.
8. `tools/finish.ps1 -Install`, сразу после — коммит и `git push origin main`.

Новая сборка сервера при первом подключении вызывает в TIA Portal запрос доступа Openness —
его подтверждает только Biz. Поэтому установленный сервер и «дымовой» прогон — один раз на
законченную задачу, предупредив Biz; до того — `tools/inproc-call.ps1`.

## Ловушки окружения

Среда — Windows 11, оболочка PowerShell 5.1 (есть и Git Bash).

- **Не вызывать `python`** — на машине заглушка, команда зависает.
- **`gh` не установлен.** Пуш обычным `git push`.
- **Кодировка скриптов.** PowerShell 5.1 читает `.ps1` без BOM как ANSI: кириллица в таком
  скрипте превращается в мусор. Скрипт с кириллицей сохранять в UTF-8 с BOM либо обходиться
  ASCII. JSON с вызовами писать через `ConvertTo-Json | Set-Content -Encoding UTF8`.
- **Окончания строк.** В репозитории CRLF, часть файлов с BOM. `sed -i` в Git Bash и инструмент
  записи файлов оставляют LF — `tools/finish.ps1` это исправляет, запускать его перед коммитом.
- **`Try` — зарезервированное слово** PowerShell; переменная `$create` и параметр `-Create` —
  одно и то же имя.
- **Массив из одного элемента** в PowerShell: `@(,@{...})`, иначе в JSON уйдёт объект, а не
  массив.
- **Блокировка exe.** Клиент сам перезапускает установленный сервер, и тот держит
  `Install\TiaMcpServer\TiaMcpServer.exe`. Git-операция, переписывающая этот файл, тогда падает.
  Поэтому: `finish.ps1 -Install` и сразу коммит.
- **Удаление по маске** (`rm dir/*`) среда может запретить. Временные файлы держать в своей
  папке scratchpad и не чистить.
- **Статические поля `Portal`** тянут за собой сборки Siemens. Тест без TIA может вызывать
  статические методы `Portal`, но не обращаться к его статическим полям — константы для тестов
  держать в типах слоя `ModelContextProtocol`.
- **Предупреждения nullable — ошибки сборки.**
