# Отложенное — не брать без прямого поручения Biz

В плане (`../PLAN.md`) эти пункты стоят в разделе «По запросу». Здесь — подробности.

## Остальные объекты WinCC Unified

- **OPC UA-алармы** — `HmiSoftware.OpcUaAlarmTypes` (`api/unified-opcua-alarms.txt`):
  `Create(nodeId, connection, name)`. Нужны OPC UA-соединение и сервер с алармами — в
  проверочном проекте их нет.
- **Аудит** — `HmiAlarmAuditClass`, `AuditTrails` (`api/unified-audit.txt`). Нужен GMP-проект.
- **Объекты установки** — `PlantObjectTags` (`api/unified-plant-objects.txt`),
  технологическая иерархия.
- **Интегрированное HMI-соединение по PROFIBUS** — не проверено: ни у панели, ни у ПК-станции
  проверочного проекта нет интерфейса DP.

Все новые виды объектов — через типизированные свойства и с пробой (`context.md`, правило 2).

## Требует отдельного проектирования

- `changeId` и список затронутых объектов для каждой записи.
- Адресация объектов по идентификатору вместо пути.
- `dryRun` для изменяющих инструментов. Для загрузки невозможен в принципе (попытка прервать
  загрузку из обратного вызова закрыла TIA Portal); для остальных есть транзакции и
  `preview_import`.
- Матрица совместимости по версиям TIA Portal, Openness, HSP и GSD.
- Онлайн-диагностика, режим CPU, опрос состояния ПЛК.
- Из дорожной карты независимого тестирования (06.10.2026): единая проверка проекта
  (`validate_project`: несогласованные объекты, компиляция ПЛК и HMI, сводка по устройствам),
  компиляция и проверка HMI Unified, свойства и адресация модулей в аппаратной конфигурации,
  граф зависимостей ПЛК пакетами, отмена и ход долгих вызовов. Управление PLCSIM сюда не
  входит: это отдельный сервер `plcsim-mcp`.

## Код — мелкие улучшения

- Помощник для проекций коллекций (`ListMapper.Map`) вместо повторяющихся `foreach` с проверкой на null.
- Общий принтер ASCII-деревьев для дерева проекта и дерева программы ПЛК (сейчас два почти одинаковых рекурсивных метода).
- Единый отчёт о ходе для массового экспорта и импорта.
- Предупреждения nullable в `Portal*.cs` по группам дерева программы: сборка идёт без ошибок, но проверить, не осталось ли
  предупреждений (`dotnet build` показывает).
- Логирование: привести комментарий `logging` в `CliOptions.cs` к числовым режимам (1 stderr, 2 Debug, 3 журнал событий) и
  описать пункты назначения и уровни в `README.md` или `docs/logging.md`.

## Транспорт

- Streamable HTTP из проекта недоступен (`ModelContextProtocol.AspNetCore` требует .NET 8+, сервер на `net48`). Нужен ли удалённый
  доступ вообще, решает Biz; варианты: отдельный прокси на .NET 8+ или TCP через `WithStreamServerTransport`. Пока stdio хватает.
