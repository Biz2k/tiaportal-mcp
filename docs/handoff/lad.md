# Инструменты для LAD — как это сделано и что выяснено

**Состояние на 07.10.2026: сделано, вошло в 0.6.0.** Инструменты: `plc_get_lad_instructions`,
`plc_get_lad_networks`, `plc_create_lad_block`, `plc_manage_lad_networks`,
`plc_manage_lad_interface`; `plc_replace_source` принимает документ LAD-блока. Ниже — журнал
работы в порядке находок: ранние разделы описывают то, что было известно в начале, итог и
поправки — в конце файла («Итог по LAD», «Поправка»).

Область ведёт Opus (решение Biz). Другим исполнителям код LAD не менять; находку по ходу другой
задачи (формат документа, имя инструкции, отказ импорта) дописать в конец этого файла.

Что осталось открытым: ограничения текстовой формы (блоки с `PID_Compact`, с резервом памяти
или пользовательскими атрибутами, OB с событием — отклоняются), инструкции, которых на S7-1500
может не быть, FBD / STL / GRAPH / CEM — только чтение.

## Исходное состояние (06.10.2026)

Что уже есть по теме:

- `plc_create_fb` создаёт FB на LAD / FBD / STL из шаблона SimaticML (`Portal.Blocks.cs`);
  пространство имён интерфейса в шаблоне — `v5` (V21).
- `export_objects` / `import_objects` с форматом `xml` переносят блоки целиком как SimaticML.
- Насколько известно на 06.10.2026, сети и элементы LAD доступны в Openness только как XML
  блока. Это не проверялось отражением по всем сборкам — проверить первым делом
  (`tools/openness-reflect.ps1 -Name 'Network|Lad|Flg'`).
- Ограничение: импорт LAD из документов требует тегов `en-US` в `.s7res`.

Находки:

- 06.10.2026, из работы над `plc_replace_source`: у блока три текстовых представления.
  **Внешний исходник** (`.scl`, `.db`, `.udt`; `GenerateSource` / `GenerateBlocksFromSource`) —
  только SCL, STL и DB; для LAD его нет. **Документ SIMATIC SD** (`.s7dcl` + `.s7res`;
  `plc_get_block_source` с форматом `document`, `import_objects` с форматом `document`) —
  текст с обёртками `NETWORK ... END_NETWORK` и атрибутами `{ S7_Language := "SCL" }`; по
  описанию инструмента он бывает и для LAD. Это первый кандидат на чтение и запись сетей LAD
  текстом — проверить, как выглядит документ LAD-блока и импортируется ли он поверх
  существующего. **SimaticML** (`xml`) — есть всегда.
- Генерация поверх существующего блока сохраняет группу, номер и instance DB; синтаксическая
  ошибка в коде генерацию не останавливает, её видит только компиляция; компиляция запрещена
  внутри транзакции. Схема «записать → скомпилировать → при ошибке вернуть прежнее» из
  `Portal.SourceEdit.cs` годится и для LAD.

## Исследование 07.10.2026 (без новых инструментов)

Пробы на `PLC (A5)` (устройство `ET 200SP station_1`), временные блоки `MCPT_*` удалены, проект
сохранён.

**API.** Отражение по всем сборкам (`-Name 'Network|Lad|Flg|Rung|SimaticSD|Document'`): объектов
для сетей и элементов LAD в Openness V21 нет. Есть только `ExportAsDocuments` /
`ImportFromDocuments` (`DocumentImportResult`: `State`, `Messages[].Message`) и SimaticML.
`ImportDocumentOptions`: `None`, `Override`, `SkipInactiveCultures`, `ActivateInactiveCultures`.

**Документ LAD-блока — читаемый текст.** Все 56 LAD-блоков трёх ПЛК проекта (26 660 строк)
экспортируются в `.s7dcl`; защищённые know-how — нет (явный отказ). Вид:

```
{ S7_Language := "LAD"; S7_NetworkTitle := "MLC_3sB" }
NETWORK
    RUNG wire#powerrail
        Contact( "Main_Acknowledge" )
        wire#w1                      // отвод: от этой точки начинается другая ветвь
        P_Trig( "Reset_Trig" )
        Coil( "Main_Acknowledge" )
    END_RUNG
    RUNG wire#w1                     // ветвь, начатая от отвода
        "DO_Main"()
    END_RUNG
    RUNG wire#powerrail              // параллельная ветвь (ИЛИ): заканчивается в точке w1
        Contact( #B )
    END_RUNG wire#w1
END_NETWORK
```

Инструкции, встреченные в проекте: `Contact`, `I_Contact` (инверсный), `Coil`, `S_Coil`,
`R_Coil`, `Not`, `P_Trig`, `Move`, `Mul`, `Div`, `Add`, `Sub`, `Round`, `Convert`, `Scale`,
`Normalize`, `EQ_/NE_/GT_/GE_/LT_/LE_Contact`, `InRange`, `OutRange`, `Label`, `JumpCoil`, вызовы
`"FC"()`, `"InstDB"( pin := ... )`, `#Timer_0.TON( pt := ..., et => )`. Параметры типа —
атрибутом перед инструкцией: `{ S7_Templates := "SrcType := Real" }`. Имена инструкций
угадывать нельзя (`N_Contact`, `Foo` — отказ импорта); полного списка в Openness нет, источник —
экспорт существующих блоков. Локальные — `#Имя`, глобальные — `"Имя"`, бит слова — `.%X0`.

**Тексты.** Заголовки и комментарии сетей лежат в `.s7res` (YAML: `id` + тексты по языкам), в
`.s7dcl` — только идентификатор `MLC_...`. Идентификатор без файла ресурсов — отказ; обычный
текст вместо идентификатора — отказ («custom MLCID is not valid»). Текста только на `ru-RU`
достаточно (ограничение «нужен en-US» в этом проекте не проявилось).

**Импорт поверх существующего блока.**

- Только через коллекцию **той группы, где лежит блок**; через корневую — отказ «object with the
  name already exists in the plc», блок цел.
- **Номер блока НЕ сохраняется**, если в документе нет `S7_BlockNumber`: 900 стал 1. (У
  внешнего исходника SCL номер сохраняется — здесь иначе.) Инструмент обязан подставлять
  текущий номер сам.
- Instance DB остаётся, становится несогласованным, после компиляции согласован; новый вход в
  интерфейсе FB принимается.
- **Отказ импорта атомарен**: при ошибке разбора блок остаётся прежним. Сообщения конкретные:
  «Instruction 'NContact' : Pin 'bit' connection is missing», «extraneous input 'END_NETWORK'
  expecting ... Error in Line Number: 7», с текстом сети.
- Несуществующий тег импорт **пропускает**; его видит компиляция («Tag "NoSuchTag_X" not
  defined», путь `Network 1`). Значит, схема та же: импорт → компиляция → при ошибке вернуть
  прежний документ.
- `None` поверх существующего блока тоже заменяет его (отличий от `Override` не видно).
- Импорт работает внутри транзакции и откатывается вместе с ней.

**Круговая проверка** (экспорт → импорт под другим именем → экспорт → сравнение, 11 блоков
`PLC (A5)`): 8 совпали дословно, все 11 компилируются. Расхождения:

- `AI_Handler`: начальное значение `T#5000ms` вернулось как `T#5S` — то же значение.
- `Valve_Control_A`: **потеряны начальные значения встроенного `PID_Compact`**
  (`PhysicalUnit := 2`, `PhysicalQuantity := 2`, `"Retain".CtrlParams.Td := 0.0`). Блоки с
  экземплярами технологических объектов править через документ нельзя без проверки — инструмент
  должен сравнивать интерфейс до и после и отказывать при потере.
- `PSM`: собственный экспорт TIA Portal не импортируется обратно («resource file contains
  corrupted data»). Причина — **повторяющиеся идентификаторы** в `.s7res` (`MLC_qH` и `MLC_Xj`
  по три раза, с разными текстами; сети были скопированы). Обход проверен: n-е вхождение
  идентификатора в `.s7dcl` соответствует n-й записи в `.s7res`; после переименования повторов
  импорт проходит, тексты возвращаются те же.

**Чужие решения.** `eponce00/tiaopen-mcp` (V20) строит LAD из JSON через SimaticML
(`build_lad_block`, шаблоны `FlgNet`): работает для контактов, катушек, ИЛИ, таймеров, но каждая
инструкция требует своего шаблона, а неверный XML подвешивает импорт диалогом. Текстовый
документ V21 делает этот путь ненужным.

## Реализация 07.10.2026

Инструменты: `plc_get_lad_networks`, `plc_manage_lad_networks`; `plc_replace_source` принимает
документ LAD-блока. Код: `Siemens/Portal.Lad.cs` (Openness), `ModelContextProtocol/LadDocument.cs`
(разбор и сборка документа, без Openness), `LadNetworkActions.cs` (пакет действий),
`McpServer.Lad.cs` (инструменты). Тесты: `Test32LadDocument`. Прогон записи: 10 вызовов на
`MCPT_FB2`.

Решения владельца: в названии инструмента только для LAD стоит `lad`; FBD не заявляется (если
будет — отдельным инструментом); справочник инструкций обязателен, но ближе к финалу.

Найдено при реализации:

- **Локальный тег с не-ASCII именем** TIA Portal экспортирует без кавычек (`Contact( #Пуск )`) и
  в таком виде отказывается импортировать («no viable alternative at input '#?'»); принимает
  `#"Пуск"`. `LadDocument` берёт такие имена в кавычки при чтении и при записи сетей LAD. В
  объявлении интерфейса кавычки не нужны.
- **Документ без атрибутов блока** (`S7_PreferredLanguage`) TIA Portal отвергает; сервер говорит
  об этом сам, до импорта.
- Свой идентификатор текста (`MLC_mcp1`) TIA Portal сохраняет как есть и возвращает при экспорте.
  Идентификаторы различаются регистром (`MLC_3fX` и `MLC_3FX` — разные тексты): сравнивать
  только с учётом регистра.
- TIA Portal обрезает пробел в конце текста комментария при импорте.
- Смешанный блок (LAD с сетями SCL, `AI_Handler` в `PLC (A0)`, 21 сеть, 1178 строк): после
  вставки, переноса, смены заголовка и обратных действий документ совпал с исходным, кроме
  записи `T#5000ms` как `T#5S` и одного пробела в конце комментария.
- Блок с повторяющимися идентификаторами (`PSM`) читается и меняется; блок со встроенным
  `PID_Compact` (`Valve_Control_A`) получает отказ с перечнем потерянных строк, блок цел.
- Блоки FBD, CEM, STL, GRAPH (`Block_*` в `PLC (A0)`) и DB получают отказ с указанием языка.

Не проверено вживую: запись в OB (FB и FC проверены, OB только читался), ветка «возврат прежнего блока
не удался», Safety-блоки (F_LAD отвергается по языку), проект с одним языком.

Осталось: справочник инструкций LAD (имена, выводы, `S7_Templates`).

## Имена инструкций — 07.10.2026

Готового списка нет: ни в справке TIA Portal (раздел «Representation of LAD program code in
SIMATIC SD format» описывает только `RUNG`/`wire#`), ни в файлах установки (разборщик —
`Siemens.Simatic.Lang.FLD.TextLad.Parser.Impl.dll`, имён в нём почти нет), ни в чужих серверах.
Имена получены **у самого TIA Portal** скриптом `tools/lad-instruction-probe.ps1`: импорт
`Имя()` отвечает «Instruction 'Sr' : Pin 'r1' connection is missing» (имя известно, вывод
обязателен), «Not a Valid instruction» либо принимает строку как вызов блока (тогда компиляция
говорит «Имя_Callee no longer exists»). Кандидаты — названия из справки (287) и догадки.

Результат — `src/TiaMcpServer/Resources/lad-instructions.tsv`: **298 инструкций** с канонической записью
и выводами (V21, S7-1500). Колонки: имя, принятые синонимы, внутреннее имя, запись, замечания,
название из справки.

- Имя из справки принимается на входе, но возвращается в своём написании: `SR` → `S_SR`,
  `SCALE_X` → `Scale`, `NORM_X` → `Normalize`, `BLKMOV` → `S_BlockMove`,
  `MOVE_BLK_VARIANT` → `MoveBlockVariant`, `EQ_Type` → `EQ_TypeContact`.
- Имена в верхнем регистре, совпадающие с ключевыми словами, отвергаются разбором:
  `ABS`, `SIN`, `SQRT`, `MOD`, `ROUND`, `AND`, `OR`, `XOR`, `SWAP` — писать `Abs`, `Sin`, `Mod`.
- Контакты и катушки: `Contact`, `I_Contact`, `P_Contact( x, bit := m )`, `N_Contact`,
  `Coil`, `I_Coil`, `S_Coil`, `R_Coil`, `P_Coil( x, bit := m )`, `N_Coil`, `P_Trig( m )`,
  `N_Trig( m )`, `Not()`, `OK( x )`, `NOK( x )`; таймеры и счётчики катушками:
  `TP_Coil( t, pt := )`, `TON_Coil`, `TOF_Coil`, `TONR_Coil`, `RT_Coil`, `PT_Coil`,
  `SP_/SE_/SD_/SS_/SF_Coil`, `SC_Coil`, `CU_Coil`, `CD_Coil`.
- Переходы: `JumpCoil( M01 )`, `I_JumpCoil( M01 )` (переход по нулю), `ReturnCoil( x )`,
  `JumpList( k := )`, `Switch`; метка — `Label(M01)` строкой **перед** `RUNG`.
- Сравнения: `EQ_/NE_/GT_/GE_/LT_/LE_Contact( in1 := , in2 := )`, `InRange`, `OutRange`.
- 27 инструкций требуют тип: без `{ S7_Templates := "SrcType := Int" }` перед ними компиляция
  говорит «Please select a data type» (математика, сравнения, `Move`-подобные, `Round`,
  `Convert` с `[SrcType := Real, DestType := DInt]`, таймеры с `time_type := Time`). Имена
  параметров шаблона для каждой инструкции ещё не собраны.
- `Add`, `Mul`, `And`, `Or`, `Xor`, `Calculate`, `MIN`, `MAX`, `CONCAT` берут `in1, in2, ...`
  сколько нужно; `Sub`, `Div` — ровно два.
- `R_Trig`, `F_Trig`, `S_Pulse`, таймеры и счётчики IEC вызываются через экземпляр:
  `#Timer_0.TON( pt := ..., et => )`.
- Направление вывода (`:=` или `=>`) у вызовов блоков импорт исправляет сам.

**Не найдено написание** для 22 названий справки: `SET_BF`, `RESET_BF`, `MOVE_BLK`,
`UMOVE_BLK`, `FILL_BLK`, `UFILL_BLK` (имена `MoveBlock`, `U_MoveBlock`, `FillBlock`
принимаются, но выводы не получены), старые таймеры и счётчики `S_PEXT`, `S_ODT`, `S_ODTS`,
`S_OFFDT`, `S_CU`, `S_CD`, `S_CUD`, а также `INVERT`, `CTRL_PWM`, `CTRL_PTO`, `RH_CTRL`,
`RH_GetPrimaryID`, `ACK_FCT_WARN`, `InitIOSystemSync`, `StartIOSystemSync`,
`GetIOSystemSync` (часть из них есть только на S7-1200 или в R/H-системах). Надёжный способ —
положить такую инструкцию в LAD-блок в редакторе TIA Portal и экспортировать документ.

Из справки Siemens про формат: при экспорте и импорте документа **теряются** атрибут «IEC Check»,
«Download without reinitialization» с резервом памяти, пользовательские атрибуты, «Visibility in
block calls», «Predefined actual parameter», свойства DB (только в загрузочной памяти, защита
от записи, доступность из OPC UA и веб-сервера); супервизии и алармы не экспортируются; конструкция
AT не поддерживается. Инструменты LAD это пока не проверяют и не восстанавливают.

## 07.10.2026, вторая половина дня

**Настройки блока, которые текст не несёт.** Проверено на временных блоках: атрибуты, которые
Openness умеет писать (IEC Check, автор, семейство, имя заголовка, ENO, номер), V21 кладёт в
документ, и они переживают правку. Доступность члена из HMI (`ExternalVisible`,
`ExternalWritable`) тоже сохраняется. **Теряются**: резерв памяти «Download without
reinitialization» (250 → 100), резерв retain-памяти, пользовательские атрибуты (UDA) и «UDA tag
readback». Выставить их для пробы удалось только импортом SimaticML; Openness их читает, но не
пишет, поэтому вернуть нельзя. Решение: `ReadBlockSettings` до и после записи, расхождение —
отказ с откатом. То же было в выпущенном `plc_replace_source` для SCL — исправлено так же.
Не проверено: «Visibility in block calls», «Predefined actual parameter», супервизии — Openness
и SimaticML их не показывают.

**`plc_create_lad_block`** — новый FB или FC с интерфейсом и сетями одним вызовом. OB не
создаётся (нужно событие). Первый настоящий блок, созданный инструментами: `Demo_Pump_Control`
в `PLC (A0)` — FC, 9 сетей (фиксация и сброс аварии, гистерезис по уровню, пуск с самоподхватом
и параллельными ветвями, счётчик пусков, `Normalize` + `Mul`). Создан с первого вызова; два
предупреждения компилятора (чтение выхода) убраны через `plc_manage_lad_networks`.

**`Block_LAD`** владельца в `PLC (A0)` дал недостающие имена: `MoveBlockI` (MOVE_BLK),
`MoveBlockU` (UMOVE_BLK), `FillBlockI` (FILL_BLK), `S_BitfieldCoil` (SET_BF),
`R_BitfieldCoil` (RESET_BF), и образцы шаблонов: `Swap` — `SrcType := Word`; `Round`, `Ceil`,
`Floor`, `Scale`, `Normalize`, `Convert` — `[SrcType := Real, DestType := Int]`. Добавлены в
`lad-instructions.tsv` (303 инструкции).

**Замечено:** `plc_get_block_source` с форматом `document` отказывает на несогласованном блоке,
хотя документ экспортируется и с него (`plc_get_lad_networks` читает). Лишнее ограничение — снять.
В установке есть Startdrive V21 Update 1 (видно в заголовке SimaticML) — к пункту 4.1 плана.

## 07.10.2026, вечер

**Комментарии переменных интерфейса.** `// текст` в объявлении TIA Portal при импорте молча
отбрасывает; комментарий члена — это `{ S7_MLC := "id" }` перед ним и текст в `.s7res`.
`LadDocument.AdoptMemberComments` превращает `Start : Bool;   // текст` в такую ссылку (и
вливает её в уже имеющийся блок атрибутов члена), `HeadWithComments` показывает обратно.

**OB.** Документ не несёт событие OB: импорт поверх «Startup» (OB100) и «Cyclic interrupt» (OB30)
оставляет OB программного цикла с номером 1; `S7_BlockNumber` в документе не помогает. Запись в
такой OB откатывается с отказом (`SecondaryType`, `PriorityNumber` в `UncarriedBlockSettings`).
OB программного цикла (`Main`) меняются: вставка и удаление сети проверены.

**Экземпляры системных FB.** `plc_create_instance_db` для `TON`, `CTU` не работает (ищет FB в
ПЛК). Рабочие пути: мультиэкземпляр в интерфейсе FB (`Timer_0 : TON_TIME;`, вызов
`#Timer_0.TON( ... )`) или DB из исходника через `plc_create_scl_block`:
`DATA_BLOCK "T1" {InstructionName := 'TON_TIME'; LibVersion := '1.0'; S7_Optimized_Access := 'TRUE' } NON_RETAIN TON_TIME BEGIN END_DATA_BLOCK`,
вызов `"T1".TON( pt := T#2s, et => )` с `{ S7_Templates := "time_type := Time" }` (для счётчика
`CTU_INT` и `value_type := Int`). Проверено в FC, компилируется. Подсказка добавлена в отказ
`plc_create_instance_db`.

**Поиск.** `plc_find_in_code` ищет и в LAD-блоках (по документу).

**Параметры типа** (перебор с компиляцией): один тип `SrcType := Int` — `Abs`, `Add`, `Mul`,
`Neg`, `Sub`, `Div`, `Mod`, сравнения, `InRange`, `OutRange`; только `Real`/`LReal` —
тригонометрия, `Sqr`, `Sqrt`, `Ln`, `Exp`, `Frac`; битовые строки `SrcType := Word` — `And`,
`Or`, `Xor`, `Swap`; пара `[SrcType := Real, DestType := DInt]` — `Round`, `Ceil`, `Floor`,
`Trunc`, `Convert`, `Scale`, `Normalize`. У `Calculate` текстовая запись выражения не найдена.

**`plc_get_lad_instructions`** отдаёт синтаксис и таблицу
`src/TiaMcpServer/Resources/lad-instructions.tsv` (встроена в сервер, 300 инструкций).

## 07.10.2026, завершение

**`plc_manage_lad_interface`** (`LadInterface.cs`): правка интерфейса по одной переменной на
тексте объявления — `add` (секция создаётся на своём месте, если её нет), `update` (тип,
начальное значение, комментарий, новое имя с переименованием `#Имя` в сетях), `delete`
(опустевшая секция убирается: TIA Portal пустых не пишет, и оставленная выглядела бы потерей).
Члены структур не затрагиваются. Проверено вживую на FB с instance DB: добавление в input, temp,
constant, переименование на кириллическое имя, смена типа и начального значения, удаление
используемой переменной (возврат прежнего блока), `compile='software'`.

**`Calculate`**: выражение пишется атрибутом `S7_Expression` рядом с типом —
`{ S7_Templates := "SrcType := Real"; S7_Expression := "(IN1 + IN2) * IN3" }`; входов столько,
сколько использует выражение. Имя атрибута нашлось в строках разборщика
(`S7_Expression`, `S7_Relation`); компилируется.

**Ещё имена**: `Inv` (INV), `S_PulseExt` (S_PEXT), `S_OnDelay` (S_ODT), `S_OffDelay` (S_OFFDT) —
имена TIA Portal знает, выводы старых таймеров не выяснены. Не найдены: `S_ODTS`, счётчики
`S_CU`, `S_CD`, `S_CUD`, и инструкции, которых на S7-1500 может не быть (`CTRL_PWM`,
`CTRL_PTO`, `RH_CTRL`, `RH_GetPrimaryID`, `ACK_FCT_WARN`, три `...IOSystemSync`).

**Разработка без запросов доступа.** TIA Portal спрашивает доступ Openness для каждой новой
сборки сервера (в списке разрешений владельца 158 записей), а при свёрнутом окне запроса не
видно. `tools/inproc-call.ps1` загружает сборку внутрь PowerShell, которому доступ дан один раз,
и вызывает методы инструментов по файлу вызовов `mcp-call.ps1`. Прогон `smoke.ps1` и
`mcp-call.ps1` идут настоящим сервером и запрос вызывают: их запускать, когда владелец готов
подтвердить доступ при развёрнутом окне.

**Итог по LAD.** Инструменты: `plc_get_lad_instructions`, `plc_get_lad_networks`,
`plc_create_lad_block`, `plc_manage_lad_networks`, `plc_manage_lad_interface`; `plc_replace_source`
принимает документ LAD-блока. Остаются ограничения текстовой формы (блоки с `PID_Compact`, с
резервом памяти или UDA, OB с событием) и ненайденные имена выше.

**Поправка (вечер 07.10.2026).** Имена `S_Pulse`, `S_PulseExt`, `S_OnDelay`, `S_OffDelay`, записанные
выше как известные TIA Portal, — ошибка перебора: импорт принял их за вызовы блоков. Настоящие
имена дал блок владельца `Block_LAD`: SIMATIC-таймеры `Sp` (S_PULSE), `Se` (S_PEXT), `Sd`
(S_ODT), `Ss` (S_ODTS), `Sf` (S_OFFDT) с выводами `Top, TV, R, RT, RTBCD`; счётчики `Cu`, `Cd`,
`Cud` с `Top, [CD,] S, PV, R, CV, CVBCD`. Вывод: «принято импортом без выводов» не доказывает,
что имя настоящее — доказывает только появление выводов или блок из редактора. В справочнике
исправлено; ненайденными остаются лишь инструкции, которых на S7-1500 может не быть.
