# 10. Подсказки при ошибках, пути, объём ответов

Приоритет: средний. Объём: три независимые части. Разделы 3.2–3.4 плана.

## Часть А. Подсказки при ошибках

- [ ] При `NotFound` во всех инструментах ПЛК предлагать кандидатов через поиск
      `plc_resolve_object_path` (сейчас только в части). Найти места:
      `PortalErrorCode.NotFound` в `Siemens/Portal.Blocks.cs`, `Portal.Types.cs`,
      `Portal.Tags.cs`, `Software/*.cs`.
- [ ] Подсказка «что делать» по коду ошибки там, где её нет. Правила — `docs/error-model.md`.
- [ ] Старые методы экспорта и импорта (`ExportXmlBlock`, `ImportFromDocuments` и другие в
      `Portal.Documents.cs`, `Portal.Sources.cs`) содержат собственные `try/catch` вместо
      `Operation.Run`. Переводить по одному методу, после каждого — модульные тесты.
      Поведение для клиента меняться не должно: сверять текст ошибки до и после.

## Часть Б. Пути

- [ ] `GetSoftwareContainer` (`Siemens/Software/Portal.Software.Core.cs`) разбирает путь к ПЛК
      отдельным кодом: не знает об экранировании `%2F` и о «Ungrouped devices». Перевести на
      общий поиск устройства (`Portal.Devices.cs`: `EnumerateDevices`, `GetDevice`,
      `GetDeviceItem`). **Осторожно:** этим методом пользуются все `plc_*` и `unified_*`
      инструменты. До правки записать, какие пути он принимает сейчас (тесты `Test9Paths`,
      плюс пути тестового проекта: `PLC (A0)`, `ET 200SP station_1/PLC (A5)`,
      `HMI Unified/HMI_RT_3`, `АРМ Unified/HMI_RT_1`), и убедиться, что все они работают после.
- [ ] `get_project_tree` отдаёт текстовое дерево без путей. Добавить структурированный вариант
      с полем `path` у каждого узла — именно те строки, которые принимают остальные инструменты.
- [ ] `plc_get_cross_references` для группы блоков отвечает «does not provide cross
      references», хотя группа найдена. Выяснить, относится ли это ко всем группам.

## Часть В. Объём ответов

Несколько инструментов возвращают десятки тысяч символов и съедают контекст модели-клиента:
`get_project_tree` (около 25 тысяч символов на тестовом проекте), `get_devices` с полным
набором атрибутов, `hw_get_device_info`, `unified_get_tags` без фильтра (2555 тегов).

- [ ] Параметры глубины и фильтра для `get_project_tree`.
- [ ] `get_devices`: по умолчанию имя, путь и тип; атрибуты — по запросу. Это ломающее
      изменение формата ответа — отметить в `CHANGELOG.md`.
- [ ] Общий предел размера ответа с явной пометкой «обрезано: показано N из M, сузьте
      фильтром ...». Для списков — параметры `limit` / `offset` или обязательный фильтр выше
      порога.

## Готово, когда

По каждому пункту: изменение, модульный тест, где возможен, живая проверка на тестовом
проекте, запись в `CHANGELOG.md`.
