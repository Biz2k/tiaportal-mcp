# 05. Опасные вызовы Openness и мёртвый TIA Portal

Приоритет: **высокий** — речь о потере несохранённой работы пользователя. Объём: средний.

## Часть А. Аудит общего доступа к атрибутам

`GetAttributeInfos()` на аларме Unified закрывает TIA Portal. Тот же метод сервер вызывает в
других местах. Сегодня они работали, но проверены не на всех видах объектов.

Места (состояние на `8284481`):

| Файл | Строка | На чём вызывается |
|---|---|---|
| `Siemens/Portal.Unified.cs` | ~232 | HMI-тег (`GetUnifiedTags`) — проверено на 2555 тегах панели |
| `Siemens/Portal.Unified.cs` | ~347 | соединение (`GetUnifiedConnections`) — проверено на S7-соединениях |
| `Siemens/Portal.Unified.cs` | ~378 | элемент экрана или экран (`GetUnifiedScreenItemProperties`) |
| `Siemens/Portal.Unified.cs` | ~408 | динамизация |
| `Siemens/Portal.Unified.Items.cs` | ~485 | элемент экрана (`ResolveHmiPropertyName`) — в транзакции |
| `Siemens/Portal.Blocks.cs` | ~1214 | член интерфейса блока |
| `ModelContextProtocol/Helper.cs` | ~19 | любой объект: атрибуты устройств, блоков и т. д. |

Что сделать:

1. Скриптом на `tools/openness-probe.ps1` пройти **все типы элементов экрана**, какие есть в
   тестовом проекте (обе HMI, включая экраны в группах — см. задачу 01), и на одном экземпляре
   каждого типа вызвать `GetAttributeInfos()`, затем чтение каждого атрибута. По одному типу
   на запуск `Probe`, с отметкой перед каждым. Проект перед этим сохранить.
2. То же для видов динамизаций (`docs/handoff/api/unified-dynamization.txt`), обработчиков
   событий, UDT-тегов и их членов, соединений не-S7.
3. Тип, на котором вызов закрывает TIA, — в таблицу «Вызовы, закрывающие TIA Portal» в
   `docs/handoff/context.md`, и обойти в коде: для этого типа читать типизированные свойства.
4. Подумать о защите по умолчанию для `GetUnifiedScreenItemProperties`: список известных
   безопасных типов; для неизвестного типа — типизированные свойства через отражение (это
   безопасно всегда: падал именно общий доступ к атрибутам).

## Часть Б. Сервер не знает, что TIA Portal закрылся

После `NonRecoverableException` сервер считает себя подключённым и на следующих вызовах
отвечает «Access to a disposed object of type 'Siemens.Engineering.Project' is not possible».
Клиент не понимает, что случилось.

Что сделать:

1. В `Operation.Run` (или в `ErrorText`) распознавать `NonRecoverableException` и
   «disposed object»: сбрасывать состояние подключения в `Portal` и отвечать ясно — «TIA Portal
   was closed by this call / is no longer running. Unsaved changes are lost. Start TIA Portal
   and call 'connect'».
2. `get_state` должен показывать, что подключения нет.
3. `connect` после этого не должен запускать новый экземпляр сам (это уже так:
   `startIfNotRunning=false` по умолчанию) — проверить.
4. Модульный тест на распознавание по тексту и типу исключения (тип — по имени, без ссылки на
   сборку Siemens в тесте).

Проверить вживую можно только закрыв TIA Portal, пока сервер подключён. `tools/mcp-call.ps1`
выполняет все вызовы файла в одном процессе сервера, поэтому между `connect` и следующим
вызовом TIA должен исчезнуть. Способ: временно, под `[DebugTool]`, не коммитя, добавить
инструмент, выполняющий заведомо опасный вызов (запись `DisplayName` HMI-тега); сохранить
проект; в одном файле вызовов — `connect`, этот инструмент, `get_state`, любое чтение;
убедиться в ответах; убрать инструмент.

## Готово, когда

- Таблица в `context.md` дополнена или подтверждено, что новых опасных типов нет (с перечнем
  проверенных типов в комментарии `Portal.Unified.cs`).
- После падения TIA сервер отвечает понятным сообщением и `get_state` не врёт.
