# 04. Проверить непроверенное в инструментах Unified

Приоритет: средний. Объём: небольшой на пункт; пункты независимы, каждый — отдельный коммит.

Это раздел 3.1 плана. Код написан и работает на проверенных случаях; ниже — случаи, которые
вживую не выполнялись. Для каждого: проба → при необходимости правка → живая проверка →
вычеркнуть в плане и здесь.

## Пункты

- [~] **Фейсплейт: типы свойств интерфейса.** `unified_manage_faceplate` проверен на теговом
      интерфейсе и строковом свойстве. Нужен тип фейсплейта со свойствами-числом, цветом,
      логическим. В библиотеке проекта посмотреть `get_library_types` с `system: "unified"`;
      если подходящего нет — попросить Biz добавить в один из типов три свойства интерфейса.
      **Частично 06.10.2026:** Булево свойство проверено вживую на `V0.0.54\AI_setting` (`Visible_Trand`: значение, `{"tag"}`, `{"script"}`, ошибка на `7` и `"maybe"`, откат). Число и цвет — **нужен образец**: в библиотеке нет типа фейсплейта со свойствами интерфейса этих видов (у проверенных типов — только строки, теги и одно булево).
- [x] **Фейсплейт: вид интерфейса заранее.** Openness не различает теговый интерфейс и
      интерфейс-свойство до попытки создать динамизацию; сейчас неверный вид отклоняется с
      подсказкой. Поискать признак: у `HmiFaceplateInterface` (`docs/handoff/api/unified-parts.txt`)
      или в типе значения `Value`.
      **Сделано 06.10.2026:** Невозможно: у `HmiFaceplateInterface` только `PropertyName`, `Value` и `Dynamizations`, признака вида нет. Тег-интерфейс принимает `TagParameterDynamization` и отклоняет `TagDynamization` (и наоборот), сообщение об ошибке подсказывает другой вид — это сохранено.
- [x] **Теги: пороги.** `Thresholds.Create()` на новом теге отвечает «New thresholds are not
      supported» (проба 06.10.2026). Выяснить: создаются ли пороги на теге другого типа данных,
      можно ли менять существующие (`Value*`, `ValueType*`), как устроены `InitialMaxValue` /
      `InitialMinValue` (объекты `UpperRange` / `LowerRange` с `Value*`, `ValueType*`).
      Вероятный итог — поддержать границы через `InitialMaxValue.Value`, а пороги только читать.
      **Сделано 06.10.2026:** Создать пороги через Openness **нельзя**: `Thresholds.Create()` отвечает «New thresholds are not supported» на всех типах данных (Real, Int, DInt, Bool, UInt, Word, String, LReal); в проекте нет ни одного тега с порогом, менять нечего. Границы — `InitialMaxValue` / `InitialMinValue` (`ValueType` None/Constant/Tag и `Value`): записываются и читаются.
- [~] **Теги: остальное.** Линейное масштабирование (`LinearScaling`, `HmiStartValue`,
      `HmiEndValue`, `PlcStartValue`, `PlcEndValue`), подстановочное значение
      (`SubstituteValue.Value*`, `SubstituteValueUsage*`), члены UDT-тега (`Members`).
      **Частично 06.10.2026:** `LinearScaling` и четыре границы шкалы, подстановочное значение и границы задаются через `unified_manage_tags` (`"SubstituteValue.Value"`, `"InitialMaxValue.ValueType"`...) и читаются в `unified_get_tags`; проверено вживую на внешнем теге. На внутреннем теге Openness отвечает «disabled fields» — сервер объясняет, что нужно сначала. Тег границы проверяется на существование. **Члены структурного тега:** это `HmiTag`, `Comment` пишется, `AcquisitionMode` принимает None/OnDemand/CyclicOnUse/CyclicContinuous; адресация члена в `unified_manage_tags` (`Тег.Член`) пока не сделана — только для архивных тегов.
- [x] **Группы таблиц тегов.** Только читаются. Создание / переименование / удаление группы и
      создание таблицы в группе — по образцу задачи 01.
      **Сделано 06.10.2026:** Инструменты `unified_get_tag_table_groups` и `unified_manage_tag_table_groups`; `unified_manage_tag_tables` принимает `group` при создании. Имена таблиц и групп уникальны на весь HMI; удаление группы удаляет её таблицы и их теги (в `Notes`); перенести таблицу между группами нельзя. Проверено вживую на панели; на ПК-станции (2 группы) — чтение.
- [x] **Соединения: другие драйверы.** Проверен S7-1200/1500. Проверить `OPC UA` и
      `SIMATIC S7 300/400`: какие у них параметры драйвера, принимаются ли. Интегрированное
      соединение с ПК-станции `АРМ Unified/HMI_RT_1` (там интерфейсы устроены иначе, чем у
      панели) и по PROFIBUS.
      **Сделано 06.10.2026:** Драйверы `OPC UA` и `SIMATIC S7 300/400` создаются и принимают параметры (OPC UA: `Protocol.DiscoveryUrl`, `SecurityPolicyUrl`, `MessageSecurityMode`, `Anonymous`, `UserName`, `Password`; S7-300/400: `Physic.LocAddress`, `Physic.LocDeviceName`, `Protocol.RemStAddress`, `Slot`, `Rack`, `Cyclic`); неверное имя параметра и недопустимое значение отклоняются со списком. `Allen-Bradley EtherNet/IP` создаётся; `Modbus TCP` и выдуманные имена — «not a communication driver». На ПК-станции то же и интегрированное соединение с ПЛК `А1.2` (общая подсеть `PN/IE_1`) создаётся. Путь ПЛК в `partner` — имя программного обеспечения (`PLC (A0)`), не путь с устройством. Без общей подсети ответ называет интерфейсы обеих сторон. **PROFIBUS не проверен**: ни у панели, ни у ПК-станции проекта нет интерфейса DP.
- [x] **Алармы: теги квитирования** (`AcknowledgmentStateTag`, `AcknowledgmentControlTag` с
      номерами бит) и запись алармов на ПК-станции.
      **Сделано 06.10.2026:** Записывается и читается на ПК-станции (аларм `MCPT_Al`: создание, ack-теги с номерами бит, удаление). Openness принимает любой тег и любой номер бита (`NoSuchTag`, `-1`, `99`) — теги проверялись и раньше, номера бит теперь отклоняются вне 0..63. `unified_get_alarms` показывает теги квитирования.
- [x] **Алармы: `AlarmParameterTags`.** Тип `Object`; на существующем аларме читается как
      строка из пробелов. Выяснить формат (на аларме, где параметры заданы вручную).
      **Сделано 06.10.2026:** Это `List<string>` из 10 слотов (на существующих алармах все пустые). Короче список — заполняются первые слоты. Openness не проверяет имена — проверяет сервер. Задаётся массивом до 10 имён тегов, читается списком занятых слотов.
- [x] **Классы алармов: системные классы.** Можно ли менять приоритет и цвета системного
      класса; `Log` — имя архива алармов (связь с задачей 03).
      **Сделано 06.10.2026:** На ПК-станции: цвета состояний и `Log` системного класса меняются; `Priority` и `Name` Openness отклоняет, удалить класс нельзя («Alarm object cannot be deleted»). `Log` — имя существующего архива алармов (несуществующее Openness отвергает исключением, теперь сервер проверяет сам и называет существующие). Проверено вживую и возвращено в прежнее состояние.
- [ ] **Списки: системные текстовые списки** (`HmiSystemTextLists`, есть `Export`/`Import`) —
      не читаются. Проба экспорта, затем чтение тем же разборщиком.
- [ ] **Списки: имя рисунка.** Не проверяется: коллекция графики Unified через Openness не
      найдена (`Project.Graphics` показывает один безымянный элемент). Поискать:
      `tools/openness-reflect.ps1 -Name 'Graphic'`.
- [ ] **`unified_debug_screen_item`** возвращает анонимный объект — нет `outputSchema`.

## Где в коде

`Portal.Unified.Faceplates.cs`, `Portal.Unified.Tags.cs`, `Portal.Unified.Alarms.cs`,
`Portal.Unified.Lists.cs`. Комментарий в начале каждого файла перечисляет, что про Openness
уже выяснено, — дополнять его находками.

## Готово, когда

Каждый пункт либо проверен и вычеркнут, либо помечен «невозможно через Openness» с причиной в
описании инструмента и в комментарии файла.
