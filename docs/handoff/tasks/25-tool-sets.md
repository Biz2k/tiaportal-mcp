# 25. Наборы инструментов: флаг `--tools`

Исполнитель: Sonnet. Приоритет: средний. Объём: небольшой. Риск для TIA Portal: нет.

## Цель

Сервер регистрирует около 140 инструментов, и все их описания попадают в контекст
модели-клиента при каждом подключении. Флаг запуска `--tools plc,unified` регистрирует только
названные области. Без флага — все, как сейчас.

## Что известно

- Регистрация: `Program.cs`, `BuildTools(allowWrite, debugTools)` — перебирает методы
  `McpServer` с `[McpServerTool]`, отбрасывает `[WriteTool]` при `--read-only` и
  `[DebugTool]` без `--debug-tools`.
- Разбор флагов: `CliOptions.cs`; тесты — `Test12CliOptions.cs`.
- Область инструмента видна по префиксу имени: `plc_`, `hw_`, `net_`, `unified_`. Без префикса —
  общие: подключение, проект, библиотеки, экспорт и импорт, загрузка, диагностика.

## Шаги

1. Области: `plc`, `hw` (вместе с `net`), `unified`, `library` (`get_libraries`,
   `get_library_types`, `get_master_copies`, `instantiate_master_copy`, `open_global_library`),
   `transfer` (`export_objects`, `import_objects`, `preview_import`), `download`. Инструменты
   подключения, проекта и диагностики (`connect`, `get_state`, `doctor`, `open_project`,
   `save_project`, `get_project_tree`...) регистрируются всегда. Область определять функцией
   от имени инструмента в одном месте (чистая логика, тест), а не атрибутом на каждом методе.
2. `--tools a,b` — список через запятую без пробелов; неизвестная область — ошибка запуска с
   перечнем допустимых (в stderr, код выхода не ноль). `--tools all` — как без флага.
3. Инструкция сервера (`Program.cs`, текст рядом с «The server runs read-only») называет
   включённые области, когда включены не все: клиент должен знать, что остальное есть, но
   выключено.
4. `doctor` / `get_state` показывают включённые области.
5. Тест: каждый зарегистрированный инструмент попадает ровно в одну область или в «всегда»;
   новый инструмент без области тест не пропускает.
6. Документация: `README.md`, `README_ru.md` (раздел о флагах запуска), пример в `samples/`.

## Готово, когда

- `tools/mcp-call.ps1 -ExeArgs '--tools plc' -ToolsOut ...` даёт только общие и `plc_*`;
  число инструментов по каждой области записано в `README.md`.
- Без флага список совпадает с `docs/tools-list.txt` (`Test_705` проходит).
- Запись в `CHANGELOG.md`, строка в `../../PLAN.md` отмечена.

## Результат (07.10.2026)

- `ModelContextProtocol/ToolSets.cs`: области в одном месте (по имени инструмента), список «всегда», разбор значения `--tools`.
  `CliOptions` читает флаг, `Program.BuildTools(..., areas)` отбирает, неизвестная область — stderr и код выхода 2.
- Живьём: число инструментов с `--tools <область>` (вместе с 12 общими): plc 78, hw 28, unified 47, library 17, transfer 15,
  download 14; без флага и с `all` — 139. Чистые числа по областям: 66, 16, 35, 5, 3, 2 (сумма с 12 общими — 139).
  `--tools plc,nope` печатает перечень и выходит с кодом 2; `get_state` и `doctor` показывают `toolAreas`.
- Тесты `Test_2800`–`Test_2806` (`Test28ToolSets.cs`): каждый инструмент ровно в одной области или в «всегда».
- **Найден дубль:** `plc_compile_software` был объявлен дважды (старая версия с `[WriteTool]` в `McpServer.Blocks.cs` и
  текущая в `Software/McpServer.Software.Core.cs`); `Test_705` дубль не видит, потому что сравнивает множества. Старая
  удалена; `Test_2805` проверяет уникальность имён.
