# 09. Непроверенные ветки: блоки, загрузка, устройства, импорт

Приоритет: средний. Объём: каждый пункт небольшой; пункты независимы.
Раздел 1 плана. Код этих веток существует, но в TIA Portal не выполнялся: ошибка проявится у
пользователя.

Общий способ: сценарий через `tools/mcp-call.ps1` на тестовом проекте, свои объекты с
префиксом `MCPT_`, уборка за собой. Для ПЛК в тестовом проекте удобно завести отдельный
`MCPT_PLC` (`hw_create_device`) и работать в нём, чтобы не трогать рабочие ПЛК.

## Итоги проверки (06.10.2026, временный `MCPT_PLC`, уже удалён)

- Копирование с `overwrite`: без него отказ с подсказкой, с ним блок и тип заменяются (номер сохраняется).
- Перемещение FB, у которого есть instance DB, и UDT, применённого в DB: Openness разрешает удаление и повторный
  импорт; DB остаётся, проект компилируется без ошибок.
- Копирование OB: номер берётся с 123 (`OB123` → копия `OB124`), класс события не влияет.
- Загрузка на недостижимую цель (адаптер VMware, ответа нет): ошибка «Connect to module ... failed» и подсказка про
  PLCSIM и адрес.
- GSD: станция из `GSD:`-идентификатора создаётся и удаляется. Станция и устройство с `/` в имени: создание, `hw_plug_module`,
  `net_connect_subnet`, `net_create_io_system`, `net_disconnect_subnet`, `hw_delete_device` работают (устройство —
  `MCPT%2FST2`, элемент — по имени как есть).
- Устройства в пользовательской группе (создана пробой: сервер групп не создаёт): `hw_get_device_info`, `get_device_item_info`,
  `hw_plug_module`, `net_*`, `hw_delete_device` находят их по `Группа/Устройство`. `softwarePath` ПЛК в группе — только
  полный `Группа/Станция/ПЛК`; короткое имя ПЛК в группе не находится (в верхнем уровне находится).
- **Дефект исправлен: `import_objects` сообщал об успехе при любом провале.** `ImportXmlBlock`, `ImportXmlType`,
  `ImportFromDocuments` возвращали `false` и глотали причину, а инструмент игнорировал результат; формат `source` передавал
  файл там, где нужна папка. Теперь каждый файл получает честный итог с причиной. `conflict_resolution`: `overwrite`
  (Override заменяет только объект той же группы; одноимённый объект в другой группе даёт отказ «already exists in this
  CPU» с подсказкой), `skip` (занятое имя — `status: skipped`), `rename` отказ (Openness не умеет). Раньше `skip`/`rename`
  для xml игнорировались.
- `export_objects` формата `source` для LAD/FBD-блока: отказ с причиной (нет исходного вида), для SCL-блока и DB работает.
- `plc_compile_software` нужен до `plc_copy_block`/`plc_move_block` у только что созданных блоков: «inconsistent» — сервер
  говорит об этом сам.

Не проверено: `RestoreAfterFailedMove` (не удалось придумать импорт, который падает после удаления; внутри транзакции
откат всё равно вернёт объект); CPU с парольной защитой и реальный ПЛК (нечем); `connect` без запущенной TIA и с
`startIfNotRunning` (закрытие TIA ради проверки не оправдано); глобальная библиотека (нужна `.al21` от Biz).
