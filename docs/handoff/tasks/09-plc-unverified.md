# 09. Непроверенные ветки: блоки, загрузка, устройства, импорт

Приоритет: средний. Объём: каждый пункт небольшой; пункты независимы.
Раздел 1 плана. Код этих веток существует, но в TIA Portal не выполнялся: ошибка проявится у
пользователя.

Общий способ: сценарий через `tools/mcp-call.ps1` на тестовом проекте, свои объекты с
префиксом `MCPT_`, уборка за собой. Для ПЛК в тестовом проекте удобно завести отдельный
`MCPT_PLC` (`hw_create_device`) и работать в нём, чтобы не трогать рабочие ПЛК.

## Блоки и типы — `Portal.Blocks.cs`, `Portal.Types.cs`

- [ ] Возврат объекта в исходную группу при сбое импорта в `plc_move_block` и `plc_move_type`
      (`RestoreAfterFailedMove`). Нужен сценарий, где импорт гарантированно падает.
- [ ] `plc_copy_block`, `plc_copy_type` с `overwrite = true`.
- [ ] Перемещение блока или типа, который используется другими объектами (UDT в DB; FB с
      вызовами): разрешает ли Openness удаление и что остаётся.
- [ ] Копирование OB: номер берётся из диапазона от 123, класс события не учитывается.
- [ ] `plc_create_fb` на LAD, FBD, STL в TIA Portal ниже V21: в шаблоне жёстко задано
      пространство имён интерфейса `v5`. Проверить нечем (установлен только V21) — оставить
      пометку в описании инструмента.

## Загрузка — `Portal.Download.cs`

Правило: PLCSIM запускает Biz; сервер его не запускает. Из обратных вызовов загрузки нельзя
выпускать исключения (см. `context.md`).

- [ ] Недостижимая цель (выключенный экземпляр, чужой адрес): ожидается ошибка с подсказкой.
- [ ] CPU с парольной защитой: сервер пароли не подставляет и должен сказать об этом в `note`.
- [ ] Реальный ПЛК — только если Biz предложит.
- [ ] (предложение) Явный параметр для шага `UserManagementDownload`; отдельные итоги по
      аппаратной и программной части в ответе.
