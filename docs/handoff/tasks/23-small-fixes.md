# 23. Мелкие исправления, найденные при приёмке

Исполнитель: Sonnet. Приоритет: средний. Объём: каждый пункт небольшой и независим; один
пункт — один коммит. Риск для TIA Portal: низкий.

Формула динамизации и обратное чтение записанных значений сюда **не входят** — их делает Opus
(`../../PLAN.md`, этап 1); `ApplyValueConverter` в `Portal.Unified.Dynamizations.cs` не трогать.

## Пункты

- [x] **Код ошибки указан дважды.** Ошибка пакетного инструмента выглядит как
      `... [code: NotFound] [code: InvalidParams; softwarePath: ...]`. Причина:
      `RunUnifiedBatch` (`Siemens/Portal.Unified.Tags.cs`, около строки 601) пишет в ошибку
      действия `ErrorText.ForClient(ex)` — текст уже с кодом и контекстом, а затем общий отказ
      пакета оформляется ещё раз. Решение: в ошибке **действия** оставить его собственный код
      (он полезнее: `NotFound` у третьего действия), а общий отказ пакета оформлять без
      повторения того, что уже названо в действиях. Проверить все пакетные инструменты
      Unified и `plc_manage_tag_table_entries`: в ответе один код на одно сообщение. Тест —
      в `Test8ErrorReporting.cs`.
- [ ] **Триггер скрипта без типа.** `{"script": ..., "trigger": {"tags": ["T1"]}}` отклоняется
      с сообщением о несуществующем типе с пустым именем. В `UnifiedDynamizationSpec.cs`
      (разбор `trigger`, `CanonicalTriggerType`): при заданных `tags` и пустом `type`
      подставлять `Tags`; при заданном `cycle` и пустом `type` — `CustomCycle`; при пустом
      всём — ошибка со списком типов, без пустых кавычек. Тесты — `Test23UnifiedDynamizations.cs`.
- [ ] **Описание `unified_set_runtime_settings`** (`McpServer.Unified.cs`) называет язык
      `en-US`, а настройки языка адресуются полным именем (`English (United States)`).
      Принимать оба вида: код культуры сопоставлять с именем языка по перечню языков runtime;
      в описании показать оба. Проверить вживую на `HMI Unified/HMI_RT_3` (включить и
      выключить язык, вернуть как было).
- [ ] **Синтаксическая ошибка в скрипте.** `unified_manage_scripts` отклоняет код, который
      TIA Portal при импорте исказил, но код с ошибкой, сохранённый дословно (`return a *;`),
      принимает как успешный. Проверить JavaScript серверу нечем — и не надо пытаться.
      Сказать это в описании инструмента и в `Notes` ответа каждой записи: синтаксис не
      проверяется; проверка — `unified_compile` (есть с 06.10.2026). Заодно проверить вживую,
      сообщает ли компиляция ошибку в модуле скриптов, и записать результат в описание.
- [ ] **Строки «только от» и «только до» в таблице диапазонов** динамизации создать нельзя
      (`RangeType` только для чтения). Сказать в описании `unified_manage_items`; при попытке
      (строка с одним из `from` / `to`) — `NotSupported` с этим объяснением, а не общая ошибка.
- [ ] **Загрузка: шаг `UserManagementDownload`.** Найти в `Siemens/Portal.Download.cs`, как
      сервер отвечает на шаги с выбором и что он делает с шагом загрузки пользователей
      (находки — раздел 09 в `../findings.md`). Добавить параметр `downloadUserManagement`
      (`keep` по умолчанию — как сейчас, `overwrite`) и в ответ — отдельные итоги по аппаратной
      и программной части, если Openness их различает. Проверка вживую требует PLCSIM —
      попросить Biz запустить; без него сделать код и тесты и написать «вживую не проверено».
- [ ] **Возврат объекта при сбое перемещения** — `RestoreAfterFailedMove`
      (`Portal.Blocks.cs`, `Portal.Types.cs`). Ветка вживую не выполнялась. Прочитать код и
      решить по факту: инструмент идёт в транзакции (`Guarded`), откат возвращает объект сам,
      значит ветка нужна только вне транзакции. Если вне транзакции код не вызывается —
      удалить ветку и сказать в комментарии, что возврат делает откат; если вызывается —
      построить сценарий и проверить.
- [ ] **Старые методы экспорта и импорта** (`Portal.Documents.cs`, `Portal.Sources.cs`) со
      своими `try/catch` перевести на `Operation.Run` и `PortalException`. Поведение не
      менять; до и после прогнать `export_objects` и `import_objects` в каждом формате на
      блоке `MCPT_`.

## Результат (06.10.2026)

- **Код ошибки указан дважды.** Проверено вживую (`unified_manage_tags`, два отказа `NotFound`: один код в конце; `plc_manage_tag_table_entries` отвечает списком результатов без кода, дубля там нет) и тестами `Test_805`–`Test_807`. Действия пакета теперь несут только причину (`ErrorText.ForAction`), код и контекст пишет общий отказ; код пакета — общий код отказавших действий, при разных кодах каждое действие называет свой в квадратных скобках (`BatchErrorText`). `unified_manage_items` код в действиях не писал.
