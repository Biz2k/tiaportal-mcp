# 11. Небольшие новые возможности

Приоритет: средний. Объём: каждый пункт небольшой и независим. Раздел 4 плана.

## 11.1. Удаление подсети — `net_delete_subnet`

`net_connect_subnet` создаёт подсеть при необходимости, а удалить её через сервер нельзя.

- Отражение: `tools/openness-reflect.ps1 -Name 'Subnet'`; у `Subnet` ожидается `Delete()`,
  подсети проекта — `Project.Subnets`.
- Проба: создать подсеть в откатываемой транзакции, подключить узел, удалить; выяснить, что
  происходит с подключёнными узлами и IO-системами — отключаются сами или удаление запрещено.
- Инструмент в `McpServer.Hardware.cs` рядом с остальными `net_*`, операция в
  `Portal.Hardware.cs`. Если на подсети есть узлы — либо отказ с их перечнем, либо параметр
  `force`; молча отключать нельзя.
- Свою тестовую подсеть называть `MCPT_...`; рабочие подсети тестового проекта (`ASU_NET`,
  `ET_NET`, `PROFIBUS_1`, `PN/IE_1`) не трогать.

## 11.2. Выбор экземпляра TIA Portal

`connect` подключается к первому найденному процессу. Если открыто несколько экземпляров,
выбрать нужный нельзя.

- `TiaPortal.GetProcesses()` даёт `Id`, `ProjectPath`, `Mode` каждого.
- Инструмент чтения `get_tia_instances` (без подключения) и необязательные параметры `connect`:
  `processId` или `projectPath`.
- `Portal.ConnectPortal` в `Siemens/Portal.cs`. Поведение по умолчанию не менять.
- Проверка требует двух экземпляров TIA — согласовать с Biz (второй экземпляр — это память и
  лицензии).

## 11.4. Интегрированные соединения: остаток

`unified_manage_connections` создаёт интегрированное HMI-соединение через
`CommunicationManagement` (`docs/handoff/api/hw-connections.txt`). Там же есть другие виды
соединений (`S7Connection`, `TcpConnection`, `IsoOnTcpConnection`...) между ПЛК. Инструмента
для них нет. Делать только по запросу Biz: `net_get_connections` (чтение — в тестовом проекте
есть `S7_Connection_1` между `PLC (A0)` и `PLC (A5)`) и затем `net_manage_connections`.
