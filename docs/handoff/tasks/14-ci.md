# 14. Непрерывная интеграция

Приоритет: низкий; только после решения Biz (задача 12.5). Объём: небольшой. Раздел 2.4 плана.

## Цель

GitHub Actions на Windows: сборка решения и модульные тесты без TIA Portal на каждый пуш.

## Что выяснить сначала

1. Собирается ли проект на машине без TIA Portal. Сборки Openness подключаются через пакеты и
   разрешаются при запуске (`Siemens/Engineering.cs`, `Openness.cs`); в выводе сборки есть
   строка «Resolve Siemens.Engineering assemblies ... from C:\Program Files\Siemens\...» —
   значит, какая-то часть разрешения идёт от установленного TIA. Проверить на чистой машине
   или в контейнере нельзя локально; первый запуск Actions и покажет.
2. Какие из тестов `Test7`..`Test16` обращаются к `Openness.Initialize` или к типам Siemens:
   им нужна установка. Их придётся исключить из CI (после задачи 08, часть Б — отдельной
   категорией, например `NoTiaInstall`).
3. Лицензия Openness не позволяет раскладывать сборки Siemens в публичном репозитории — не
   коммитить `Siemens.Engineering*.dll` ради CI.

## Шаги

1. Убрать `.github/` из корневого `.gitignore` (сейчас исключён).
2. `.github/workflows/build.yml`: `windows-latest`, `dotnet build -c Release`,
   `dotnet test --filter <категория>`.
3. Если сборка без TIA невозможна — зафиксировать это в этом файле и закрыть задачу как
   «невыполнимо без самостоятельного раннера».

## Готово, когда

Зелёный прогон на `main`, либо записанная причина, почему CI невозможен.
