# 06. Остальные динамизации и события элементов Unified

Приоритет: средний. Объём: средний.

## Цель

`unified_manage_items` задаёт свойству статическое значение либо динамизацию трёх видов: тег
(`{"tag": ...}`), скрипт с кодом (`{"script": ...}`), список (`{"resourceList": ..., "tag": ...}`).
Не охвачено:

- у скриптовой динамизации — триггер (`Trigger`), асинхронность (`Async`), глобальная область
  определений (`GlobalDefinitionAreaScriptCode`);
- у привязки к тегу — конвертер значения (`ValueConverter`), `ReadOnly`, косвенная адресация
  (`UseIndirectAddressing`), адрес и тег ПЛК напрямую (`Address`, `PlcTag`, `DataType`);
- выражение (`ExpressionDynamization` с `ValueConverter`);
- мигание (`FlashingDynamization`);
- обработчики изменения свойства (`PropertyEventHandlers`) — отдельно от событий (`EventHandlers`);
- у событий — то же, что у скриптов: `Async`, глобальная область определений.

## Что известно

Справочник: `docs/handoff/api/unified-dynamization.txt`, события —
`docs/handoff/api/unified-events.txt`.

- Динамизация создаётся `Dynamizations.Create<T>(propertyName)`; у свойства она одна, другой
  вид сначала удаляется. Готовый код — `SetHmiDynamization` в `Portal.Unified.Items.cs`: он
  создаёт или находит динамизацию нужного вида и задаёт одно её свойство.
- На свойстве интерфейса фейсплейта допустимы только некоторые виды — см. комментарий в
  `Portal.Unified.Faceplates.cs`.
- Чтение: `unified_get_screen_item_properties` возвращает `_Dynamizations` со всеми атрибутами
  динамизации и `_Events` — по ним видно, как выглядит настроенное вручную.

## Шаги

1. Попросить Biz настроить на экране `A7` по одному примеру каждого вида: скрипт с триггером
   по тегу, привязку к тегу с диапазонами значений (конвертер), выражение, мигание. Прочитать
   их `unified_get_screen_item_properties` и пробой типизированных свойств — так выясняется,
   как устроены `Trigger` и `ValueConverter` (это вложенные объекты).
2. Спроектировать форму входа, не ломая существующую. Сейчас объект свойства содержит ровно
   один ключ (или `resourceList` + `tag`). Расширение — дополнительные необязательные ключи
   рядом с основным:
   `{"script": "...", "trigger": {"tags": ["T1"]}, "async": true}`,
   `{"tag": "T1", "readOnly": true, "ranges": [...]}`.
   Проверку ключей в `SetHmiItemProperty` переписать: основной ключ определяет вид, остальные
   проверяются по списку допустимых для этого вида; неизвестный ключ — ошибка с перечнем.
3. Реализовать по одному виду за раз, каждый с пробой и живой проверкой.
4. `PropertyEventHandlers` — выяснить пробой, что это и чем создаётся; возможно, отдельное поле
   действия рядом с `events`.

## Готово, когда

Каждый вид из списка либо задаётся и читается обратно, либо помечен невозможным с причиной.
Существующие вызовы `unified_manage_items` работают без изменений (проверить набором вызовов
из `README.md`).

## Риски

Новые виды объектов (`Trigger`, `ValueConverter`, их вложенные коллекции) — только
типизированные свойства и пробы перед использованием.
