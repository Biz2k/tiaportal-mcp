# 02. Скрипты WinCC Unified

Статус: **сделана 06.10.2026** (см. «Что выяснено» в конце).

Приоритет: высокий (запрошено Biz). Объём: средний. **Нужен образец от Biz** — см. «Блокер».

## Цель

Инструменты для глобальных скриптов (модулей скриптов) Unified: прочитать модули с их
функциями и кодом, создать и изменить модуль, удалить.

Скрипты на событиях и в динамизациях элементов сюда не относятся — они уже задаются через
`unified_manage_items` (`events`, `{"script": ...}`); их остаток — в задаче 07.

## Что известно

`docs/handoff/api/unified-scripts.txt` — весь API в шести строках:

- `HmiSoftware.Scripts` — `HmiScriptModuleComposition`: `Export(DirectoryInfo)`,
  `Import(DirectoryInfo)`, `Import(DirectoryInfo, String name)`. Нет `Create`, нет `Find`.
- `HmiScriptModule`: `Name`, `Export(DirectoryInfo)`, `Export(DirectoryInfo, String name)`.
  Нет `Delete`, нет доступа к коду.

То есть, как и у текстовых списков, объектной модели содержимого нет: только экспорт и импорт
файлов. Образец такого инструмента — `Portal.Unified.Lists.cs` (временная папка, запись файла
в виде, в каком его пишет TIA, проверка обратным экспортом).

## Блокер

В тестовом проекте **нет ни одного модуля скриптов** (`Scripts.Count` = 0 в обоих HMI), и
экспорт пустой коллекции не создаёт файлов. Формат файла экспорта неизвестен, а создать модуль
через Openness, чтобы посмотреть, нельзя. Попросить Biz: «Создайте в `HMI Unified` в разделе
Scripts один модуль с двумя функциями (одна с параметрами и возвращаемым значением) и одним
глобальным определением». С текстовыми списками было так же: формат диапазонов выяснился
только из списка, сделанного вручную.

Пока образца нет, задачу можно начать с пункта 1 и остановиться.

## Шаги

1. Убедиться отражением, что в других пространствах имён нет ничего про скрипты:
   `tools/openness-reflect.ps1 -Name 'Script'`. (Классы `ScriptDynamization` и обработчики
   событий — это другое.)
2. С образцом: экспортировать (`sw.Scripts.Export(dir)` и `module.Export(dir)`), посмотреть,
   какие файлы появляются (вероятно `.js` и файл описания), в какой кодировке, как устроены.
3. Пробой в откатываемой транзакции выяснить поведение `Import`:
   - заменяет ли существующий модуль целиком или сливает;
   - что делает с модулями, которых нет в файле;
   - что происходит при синтаксической ошибке в коде;
   - что возвращает (у списков `Import` возвращает `bool`).
4. Удаление: у `HmiScriptModule` нет `Delete()`. Проверить, есть ли способ (импорт пустого
   набора? `IEngineeringObject` и сервис?). Если нет — честно написать в описании инструмента,
   что удаление невозможно.
5. Инструменты:
   - `unified_get_scripts(softwarePath, moduleName = "")` — модули, функции, код;
   - `unified_manage_scripts(softwarePath, actions)` — запись модуля целиком и, если удастся,
     удаление. Всё или ничего, с обратным чтением.
6. Тесты без TIA: разбор и сборка файлов на настоящем образце экспорта.

## Готово, когда

- Модуль, сделанный Biz, читается с кодом функций.
- Новый модуль создаётся, читается обратно без расхождений, изменяется.
- Проверено на панели и на ПК-станции.
- Описано, что невозможно (удаление, если так), и это видно в описании инструмента.

## Риски

- `Import` может молча отбрасывать непонятое, как у списков, — обратное чтение обязательно.
- Код скрипта — многострочный текст с кавычками и обратными косыми чертами; если формат YAML,
  `SimpleYaml` читает блочные тексты `|-`, но проверить на настоящем файле. Если формат иной
  (чистый `.js`), `SimpleYaml` не нужен.

## Что выяснено

Образец Biz: модули `TestGlobalModule` (две функции, глобальные определения, кириллица в комментариях) и
`Global module` (пустой) в `HMI Unified`. Формат и поведение `Import` описаны в заголовке
`Portal.Unified.Scripts.cs`; чистая логика (разбор, сборка, сравнение) — в `UnifiedScriptCode.cs`, тесты —
`Test17UnifiedScripts.cs`.

- Модуль — два файла `<имя>.hmi.yml` и `<имя>.hmi.js` (UTF-8 без BOM, CRLF). В `.js` сначала глобальные
  определения, затем комментарий-маркер `***End of Global definition area***`, затем функции.
- `Import(папка, имя)` создаёт модуль или заменяет одноимённый целиком, возвращает `false` при неизвестном
  имени. Удаления и переименования нет (у `HmiScriptModule` нет `Delete`) — `delete` отвечает объяснением.
- Код разбирается и пересобирается: пробелы меняются; параметры по умолчанию превращаются в `b___5`;
  синтаксическая ошибка принимается молча, тело функции теряется; комментарии между функциями могут уехать
  выше маркера. Поэтому каждая запись читается обратно и сравнивается без комментариев и пробелов вне строк.
- Проверено вживую на `HMI Unified/HMI_RT_3`: создание, замена, ошибки (дубль, нет модуля, имя, параметр по
  умолчанию, синтаксис), откат. На ПК-станции — только чтение (модулей там нет), запись не проверялась.
- В тестовом проекте остался пустой модуль `MCPT_Mod` — удалить его через Openness нельзя, Biz может удалить
  вручную.
