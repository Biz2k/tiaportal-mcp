# 38. Аудит скриптов и динамизаций HMI Unified

Исполнитель: Sonnet. Приоритет: низкий. Объём: средний. Риск для TIA Portal: низкий — только
чтение.

## Зачем

Медленная панель Unified почти всегда объясняется числом скриптов и динамизаций с цикличным
триггером. В TIA Portal такой сводки нет; Siemens даёт её отдельным дополнением
(`TIA-Add-In-ShowScripts`, <https://github.com/tia-portal-applications>, файл
`src/ShowScripts/AddScriptsToList.cs` — образец того, что считать). У них полный обход большого
проекта идёт до 30 минут: нужен постраничный вывод по экранам.

## Что известно

- Динамизации и события элемента сервер уже читает: `unified_get_screen_item_properties`
  (`Portal.Unified.Dynamizations.cs`, `Portal.Unified.Screens.cs`); виды динамизаций — тег,
  выражение, скрипт, мигание; у скрипта триггер — цикл (`T100ms`, `T1s`, ...) или теги.
- Постраничный вывод — `ListPage`, `Paging` (`findings.md`, раздел 24).
- Чтение не должно менять проект: «дымовой» прогон чтения проверяет `isModified` после каждого
  вызова.
- В проверочном проекте: панель `HMI Unified/HMI_RT_3` (74 экрана с группами) и ПК-станция
  `АРМ Unified/HMI_RT_1`.

## Что сделать

1. `unified_get_dynamization_summary(softwarePath, screenFilter = "", limit, offset)` — страница
   по экранам (по умолчанию 20 экранов). Для каждого экрана:
   - число элементов; число динамизаций по видам;
   - скриптовые динамизации по триггерам: имя цикла → число, «по тегам» → число;
   - число событий со скриптом (у экрана и у элементов);
   - число экземпляров фейсплейтов по типам;
   - элементы за пределами экрана (`Left`/`Top` вне `Width`/`Height` экрана) — имена, не больше 20;
   - теги, названные в динамизациях и триггерах, — число разных; список — только с
     `withTags: true`.
   В `meta` — итог по прочитанной странице и общий `total` экранов.
2. Замерить время на одном экране и на странице в 20; записать в описание инструмента, чтобы
   модель знала цену вызова. Если страница идёт дольше 30 секунд — уменьшить страницу по
   умолчанию.
3. Теги внутри текста скриптов не разбирать (JavaScript серверу проверять нечем): считать только
   теги триггеров и динамизаций «тег» и «выражение». Сказать это в описании.
4. Тесты на сведение (чистая часть — подсчёт по уже прочитанным описаниям элементов), вызовы в
   `tools/smoke/read.json`, README (оба), `CHANGELOG.md`, `docs/tools-list.txt`.

## Готово, когда

Сумма страниц по `HMI Unified/HMI_RT_3` равна числу экранов; числа одного экрана сверены с
`unified_get_screen_item_properties` его элементов вручную; «дымовой» прогон чтения проходит.
