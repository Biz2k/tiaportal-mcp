# A SINAMICS drive and a PLC axis

A drive (S210, or G120 with a power module) in the IO system of a PLC, its telegram and motor, and an axis of the PLC bound to it. The tools are those of the `hw`, `drive` and `plc` areas. Nothing here goes online: the drive is only configured in the project.

1. Find the type. `hw_search_catalog` with a part of the article number: `S210` gives `OrderNumber:6SL3210-5HB10-1xFx/V5.2.3/S210` (several versions are listed, take the one the user wants); `6SL3244-0BB12` lists Control Units of the G120 (`OrderNumber:6SL3244-0BB12-1FA0/4.7.13`); `6SL3210-1PE11` lists Power Modules (`OrderNumber:6SL3210-1PE11-8ULx/-`).
2. The PLC and its network are as in [Add a PLC and connect it to a subnet](add-plc-and-subnet.md): `net_connect_subnet` on the PLC interface, then `net_create_io_system`.
3. Create the drive: `hw_create_device` with the type, a `name` for the drive and a `stationName`. The S210 answers with the items `Drive control` and the drive; the G120 with a rack and the Control Unit.
4. G120 only: plug the Power Module with `hw_plug_module` (`deviceName` = the station, `parentItemName` = the Control Unit, `positionNumber` 3, the Power Module `typeIdentifier`). Until then the drive has 4492 parameters and no motor data; after it 5149. An S210 has its power part in the device.
5. Put it into the IO system: `net_connect_subnet` and `net_connect_to_io_system` with `interfaceName` `PROFINET interface` (the drive interface; the PLC one is `PROFINET interface_1`). Subnet first, then the IO system.
6. Look at the drive objects: `drive_get_objects` with the station name returns the `path` of each object (`MCPT_Drv/Drive control` for the S210, `MCPT_DrvG/MCPT_G120` for the G120) and its telegrams. Use this path as `drivePath` below.
7. Telegram: `drive_manage_telegrams` with actions `change` (`number`, optionally `type` `main`, `supplementary`, `additional`, `torque`), `insert` and `erase`. The S210 starts with 105 (position control); an axis that needs an encoder with the setpoint takes 3 or 105. The G120 starts with 1; asking for the telegram it already has is refused, as is a number the drive object does not take - nothing is changed then.
8. Motor, G120: `drive_set_motor` with `motorType` (`InductionMotor`) and `values` of the required data (`p305` rated current, `p307` power, `p311` speed; `p304` and `p310` keep their defaults). The answer lists what the drive now holds, including the data you did not give. Needs the Power Module of step 4.
9. Parameters: `drive_get_parameters` with `names` finds a parameter by name or text (`p1082` is the maximum speed of the S210, `p1120` the ramp-up time of the G120; a name the drive object does not have is listed under `notFound`). A parameter with indexes is written per element, `p1082[0]`; `p1082` alone is refused and says so. `drive_set_parameters` returns before and after and the unit.
10. The axis: `plc_create_technology_object` with `type` `TO_PositioningAxis` (position control, with an encoder) or `TO_SpeedAxis`, then `plc_connect_technology_object` with `name` of the axis and `drivePath`. The answer lists the connections with their addresses, e.g. `drive: connected (input address 256, output address 256)`. A telegram that carries encoder values (3, 5, 105) connects the encoder as well. `plc_get_technology_objects` and `plc_set_technology_parameters` read and set the axis parameters (`DynamicLimits.MaxVelocity`).
11. `hw_compile` with the station of the PLC. Read the messages:
    - Three errors about the password for confidential configuration data and for full access came with the new CPU used here (a 1511-1 PN, firmware V2.9) in this project. Clear them as in [Protect a PLC](protect-a-plc.md) (`sec_set_plc_configuration_protection`, then `sec_set_plc_access_level` with `passwordFor` `FullAccess`).
    - A Control Unit with the telegram of step 7 and the Power Module compiles clean (checked); the same project with the S210 does not: `Topology error. There is no connection possibility between the sync master ... and the sync slave ...`. The S210 is a synchronised (IRT) device and needs its port connected to a port of the PLC in the topology; no tool of this server connects ports yet. Say so, do not work around it.
    - With both drives in the IO system the G120 also reported `No update time can be calculated`; it went away with the S210 removed.

To undo: `plc_delete_technology_object`, then `hw_delete_device` for each drive and for the PLC station, then `net_delete_subnet` (`force: true` if it still names interfaces). Every write is in memory until `save_project`.

Checked live on V21 (08.10.2026): the whole sequence for an S210 with a positioning axis (telegram 3) and for a G120 with PM240-2 and a speed axis; the compile result is as described. Not checked: the S210 with the ports interconnected, a motor of an S210, the multi-axis S120, anything online (parameters of a running drive, download).
