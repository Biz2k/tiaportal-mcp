# Add a device from the catalog

What can be added to a project, and how to add a device that is not a PLC: an ET 200SP station built module by module, or a device from a GSD file. The PLC itself is [Add a PLC and connect it to a subnet](add-plc-and-subnet.md).

1. What is installed: `get_installed_software` returns the products with their options (STEP 7, WinCC, Startdrive and which drive families), the size of the catalog and `gsdFiles` - each GSD / GSDML file that TIA Portal has installed, with the catalog folder it sits in and the number of devices and modules. A device whose file is not in this list cannot be added. The server does not install GSD files; the user does that in TIA Portal (Options > Manage general station description files) and then asks again.
2. Browse: `hw_get_catalog` with a `path` shows the folders of one level and the number of entries in each; the folder that holds entries lists them with `typeIdentifier`, `typeName`, `articleNumber`, `version`. The separator of the path is `\`; a `/` belongs to a name (`Distributed I/O`, and some devices are called `...ST02/03`, which makes their folder unreachable by path: search instead). `limit` and `offset` page a long folder.
3. Search: `hw_search_catalog` with `query` finds entries by a part of the article number, the type name or the identifier, and gives `catalogPath` as well. A GSD device is found by a part of its file name (`EUCHNER-EKS_3`), so searching is quicker than browsing for `Other field devices`.
4. The identifiers have three forms:
   - `OrderNumber:6ES7 511-1AK02-0AB0/V2.9` - a device or module with an order number and a firmware version (take the version the user wants; the catalog lists several);
   - `System:Device.ET200SP`, `System:Rack.ET200SP` - the empty station and the rack of a modular station;
   - `GSD:<file>/DAP/<id>` for the head of a GSD device and `GSD:<file>/M/<id>` for its modules.
5. Create: `hw_create_device` with `typeIdentifier`, `name` (the device) and `stationName`.
   - A device with an order number (a PLC, a drive, an IO head with its own station) comes with its items; the answer lists them.
   - An ET 200SP is built: `hw_create_device` with `System:Device.ET200SP` makes an empty station ("Empty station ... created"); then `hw_plug_module` with an empty `parentItemName`, position 0 and `System:Rack.ET200SP` adds the rack; then the head module into the rack at position 0 (`OrderNumber:6ES7 155-6AU00-0BN0/V1.1`), and the I/O modules at 1, 2 ... (`OrderNumber:6ES7 131-6BH01-0BA0/V0.0`, a DI 16x24VDC ST). A position that is taken is refused and the answer lists the occupied ones, with the names.
   - A GSD device comes with the modules its GSD file defines as the default (the DataMan reader with seven, the Euchner EKS with two, the KUKA KRC4 with two), plugged at positions 1 ... n. `hw_plug_module` into them is refused, and so is a position behind them: on the three devices tried no free slot was offered. Another module combination has to be chosen in TIA Portal; no tool unplugs a module.
6. Connect it: the interface is named differently per device - `PROFINET interface` on ET 200SP and drives, `Interface` on the DataMan and the Euchner; `hw_get_topology` shows the name of the item that carries a network interface (a name that does not exist is refused and the top-level items are listed). Then `net_connect_subnet` and `net_connect_to_io_system` (subnet first, then the IO system of the PLC), as in the PLC recipe.
7. `hw_compile` of the station of the PLC reports what is missing (an IO device without an address, a module that does not fit). A bare GSD device in a PLC-less project compiles clean (checked with the KUKA station); a device in an IO system whose telegrams do not fit the update time reports `No update time can be calculated` (seen with a drive, see [A drive with an axis](drive-with-axis.md)).

To undo: `hw_delete_device` for each station you made, then `net_delete_subnet` (`force: true` if it still has interfaces). Every write is in memory until `save_project`.

Checked live on V21 (08.10.2026): the browse of the catalog down to a GSD module, the search by article number and by GSD file name, an ET 200SP with rack, head module and DI plugged and connected to the IO system of a PLC, the refusal of a taken position, GSD devices (Cognex DataMan 470, Euchner EKS, KUKA KRC4) created, the Euchner one connected to the IO system, the KUKA one compiled; all deleted afterwards. Not checked: installing a GSD file, the KUKA interface name, a GSD device with a free module slot, PROFIBUS devices (GSD of PROFIBUS DP / PA is in the catalog under `Other field devices` but was not created).
