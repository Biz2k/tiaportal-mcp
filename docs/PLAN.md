# План работ

Состояние на 07.10.2026, коммит `2e73021`: 137 инструментов, 112 модульных тестов без TIA Portal,
«дымовой» прогон чтения (`tools/smoke.ps1`) проходит на проверочном проекте.

Здесь только то, что осталось сделать. Что сделано и почему — в `CHANGELOG.md`; подробности по
закрытым задачам, включая находки про Openness, — в `docs/handoff/tasks/`. Как работать с
проектом (разрешения, рабочий цикл, скрипты) — `docs/handoff/context.md` и `docs/handoff/recipes.md`.

Пометки у пунктов:

- **дефект** — работает не так, как заявлено;
- **осталось** — начато или запланировано, но не закончено;
- **предложение** — в прежних планах этого не было;
- **по запросу** — делать только по слову владельца.

## Правила

Действуют для всех пунктов; полные формулировки — в `docs/handoff/context.md`.

- Внутри транзакции TIA Portal нельзя «перехватить и продолжить»: после любого исключения
  Openness фиксация запрещена. Пакетные инструменты работают по принципу «всё или ничего»,
  всё проверяемое проверяется до обращения к Openness.
- Некоторые вызовы Openness закрывают TIA Portal вместе с несохранённым проектом. Вызов на
  новом виде объектов сначала пробуется отдельным скриптом (`tools/openness-probe.ps1`);
  известные опасные вызовы — в таблице в `docs/handoff/context.md`.
- Openness многое принимает молча и молча искажает. Записанное читать обратно и сравнивать.
- Прежде чем считать, что Openness чего-то не умеет, искать по всем его сборкам
  (`tools/openness-reflect.ps1 -Name ...`).
- PLCSIM запускает владелец; сервер его не запускает.
- Проверено вживую, проверено только тестами, не проверено — писать прямо.

## 1. Дефекты и недочёты

Найдены 07.10.2026 при приёмке работы по задачам `docs/handoff/tasks/` и независимым
тестированием сервера на проекте `TestProject` 06.10.2026 (помечены «тестирование»).

- [ ] **Кросс-ссылки всего ПЛК не работают** — дефект, тестирование. `plc_get_cross_references`
      с пустым `objectPath` отвечает `NotSupported` («does not provide cross references»), хотя
      описание инструмента обещает для пустого пути «весь ПЛК». Воспроизводится на двух ПЛК; по
      одному блоку инструмент работает. У программы ПЛК, как и у группы блоков, своей службы
      перекрёстных ссылок в Openness нет. Для группы ответ уже собирается из её блоков
      (`Software/Portal.Software.CrossReferences.cs`); сделать то же для корня — блоки, типы,
      таблицы тегов — с `limit` / `offset` и пометкой об усечении, потому что на ПЛК в сотню
      блоков ответ большой. Если какая-то часть объективно недоступна, сказать это в ответе,
      а не общим `NotSupported`.
- [ ] **`save_as_project` и расширение в пути** — дефект, тестирование. Путь передаётся в TIA
      Portal как папка без проверки: `...\X.ap21` создаёт папку `X.ap21` с файлом
      `X.ap21.ap21`, а внутри существующей папки завершается ошибкой «storage medium is no
      longer available». Отрезать расширение проекта либо отклонять такой путь с объяснением;
      в описании параметра написать, что это папка нового проекта. Заодно перевести
      инструмент на общий каркас (`Operation.Run`, `PortalException`): он старый.
- [ ] **`connect` без параметров при одном экземпляре TIA Portal** — проверить, тестирование.
      В отчёте сервер сообщал `Connected=false` при открытом TIA Portal, подключение прошло
      после явного указания PID. Неясно, вызывался ли `connect` без параметров. Проверить
      одним вызовом; при одном экземпляре он обязан подключаться без PID. Заодно: при двух
      экземплярах `connect` без параметров берёт первый в списке, которым может оказаться
      пустой, — предпочитать экземпляр с открытым проектом.
- [ ] **Сохранение одновременно с чтением** — проверить, тестирование. Параллельные
      `save_as_project` и `get_project_tree` прошли без сбоя, но сам случай показал, что так
      вызвать можно. Убедиться, что `save_project`, `save_as_project`, `close_project` и
      `open_project` идут под той же блокировкой, что и остальные операции (`Operation.Run`), и
      что чтение, начатое до смены проекта, не работает потом с объектами закрытого проекта.
- [ ] **Формула динамизации не читается обратно** — дефект. `unified_manage_items` с
      `{"tag": ..., "formula": ...}` или `{"expression": ...}` отвечает «успех», даже когда TIA
      Portal заменил формулу: `$value * 2` сохранилась как `'InvalidTag'`. После записи читать
      `ValueConverter.Formula` и при расхождении завершать действие ошибкой с тем, что
      сохранилось. Заодно записать в описание инструмента правильный вид формулы — на
      образцах экрана `A7`. Код: `ApplyValueConverter` в `Portal.Unified.Dynamizations.cs`.
- [ ] **Обратное чтение у остальных свойств, принимаемых молча** — предложение, обобщение
      предыдущего. Пройти изменяющие инструменты Unified и для каждого значения, которое
      Openness может исказить без ошибки (формулы, выражения, имена циклов, ссылки на теги и
      списки внутри динамизаций, условия таблиц), решить: проверять заранее, читать обратно
      или честно сообщать в `Notes`, что значение не проверяется.
- [ ] **Синтаксическая ошибка в скрипте ловится не всегда** — дефект описания.
      `unified_manage_scripts` отклоняет код, который TIA Portal при импорте исказил, но код
      с ошибкой, сохранённый дословно (`return a *;`), принимает как успешный. Проверить
      JavaScript серверу нечем: сказать это в описании инструмента и в `Notes` ответа, убрать
      из `docs/handoff/tasks/02-unified-scripts.md` утверждение, что случай покрыт.
- [ ] **Код ошибки указан дважды** — недочёт. Ошибка пакетного инструмента выглядит как
      `... [code: NotFound] [code: InvalidParams; softwarePath: ...]`: текст действия уже
      содержит свой код, а общий код пакета добавляется сверху. В `RunUnifiedBatch`
      (`Portal.Unified.Tags.cs`) и в `ManageUnifiedItems` брать у действия текст без кода.
- [ ] **Триггер скрипта без типа** — недочёт. `{"script": ..., "trigger": {"tags": [...]}}`
      отклоняется с «Trigger type '' does not exist». При заданных тегах тип `Tags` очевиден:
      подставлять его.
- [ ] **Описание `unified_set_runtime_settings`** называет язык `en-US`, а настройки языка
      адресуются полным именем (`English (United States)`). Исправить описание или принимать
      оба вида.
- [ ] **Запись на ПК-станции Unified не проверена** — осталось. На `АРМ Unified/HMI_RT_1`
      вживую проверено чтение и запись алармов; не проверялась запись экранов и групп экранов,
      скриптов, архивных тегов, динамизаций, настроек runtime. Пройти по одному удачному
      вызову на инструмент, с объектами `MCPT_` и уборкой.
- [ ] **Пустой модуль скриптов `MCPT_Mod`** остался в проверочном проекте: Openness не умеет
      удалять модули. Удалить вручную в TIA Portal.

## Что невозможно через Openness V21

Выяснено и закрыто; здесь — чтобы не выяснять заново.

| Что | Почему |
|---|---|
| Пороги HMI-тега | `Thresholds.Create()`: «New thresholds are not supported» на всех типах данных |
| `DisplayName` HMI-тега | запись закрывает TIA Portal |
| Удаление и переименование модуля скриптов | у `HmiScriptModule` нет `Delete` |
| Чтение и создание циклов Unified | у `HmiSoftware` нет коллекции циклов |
| Вид свойства интерфейса фейсплейта заранее | у `HmiFaceplateInterface` нет признака вида |
| Чтение списков, являющихся типами библиотеки | экспорт версии типа не содержит записей |
| Проверка имени рисунка в графическом списке | коллекция графики Unified недоступна |
| Отличить фейсплейт Advanced от Professional | один класс без признака системы |
| Таблица Expression конвертера значения | создание строки закрывает TIA Portal |
| Экраны и элементы классического WinCC | нет объектной модели, только XML |
